What we found in Hugging Face's community robot data

We scanned every sub-dataset of lerobot/community_dataset_v3 (1,754 datasets from 488 contributors) on a laptop overnight. Every finding below comes from a deterministic check, involves no AI judgment, and was verified by hand.

7.1% of all episodes (5,125) are exact motion duplicates (every joint, every frame) of episodes elsewhere in the collection. 777 duplicated recordings span different contributors, and 97 dataset pairs are at least 80% the same recordings. In a pretraining mix, duplicates silently over-weight some demos and leak between train and test splits. That is roughly 26 hours of duplicated robot data (≈ 5,125 episodes × 18.1 s average).

Reviewing all 364.6 hours by hand would take about 365 person-hours. Retake's integrity layer scanned it for $0; running the vision layer on all 72,356 episodes would cost about $80 at the measured $1.10 per 1,000 episodes.

Proof: a frozen test set, run once

50 labeled episodes from the BotFails benchmark were set aside before any tuning. The pipeline was locked (git tag v1.0-frozen) and then run on them exactly once.

How to fix it (sources found at audit time by Tavily, summarized by Nemotron 3 Ultra; every point carries a quote that code verified is in an official source)

empty episode
  • Likely cause: Episode timer expires immediately if episode_time_s is set to very low value [2]
    "Duration of each data recording episode default: 60 seconds"
  • Fix: Increase episode_time_s parameter to allow sufficient recording duration [2]
    "episode_time_s=60 Duration of each data recording episode"
no motion
  • Likely cause: Recorded actions incorrectly saved as all zeros. [2]
    "the action recorded are all set to zero"
length mismatch
  • Fix: Ensure from_timestamp matches actual video PTS to eliminate drift [5]
    "This ensures from_timestamp always matches the actual video PTS eliminating drift regardless of episode count"
  • Fix: Increase tolerance_s to mask underlying inaccuracy [5]
    "Increase tolerance_s e.g. 0.04 for 30fps or 0.06 for 15fps"
dead sensor
  • No public source with verifiable guidance was found.
duplicate episode
  • Likely cause: Duplicate episode indices cause data loss during split [2]
    "the second occurrence of 0 overwrites the first dictionary entry"
  • Fix: Remove duplicate episode IDs before splitting datasets [2]
    "Removing duplicate IDs from the input avoids the issue"
timestamp error
  • Likely cause: Video muxer receives non-monotonic DTS values [3]
    "Application provided invalid, non monotonically increasing dts"
  • Fix: Write v3 dataset in single shot avoiding cache re-entry [3]
    "embodied-data convert writes v3 in a single shot rather"
  • Fix: Re-encode video with monotonic PTS to satisfy muxer [3]
    "re-encodes video with bf=0 g=2 monotonic PTS"
human intervention
  • No public source with verifiable guidance was found.

How it works

1 · Integrity (code)Ten deterministic checks on every episode: empty, motionless, duplicated, frozen sensors, broken timestamps, video/motion mismatch, frozen or black video. Free.
2 · Motion (statistics)Per-task outliers in duration, hesitation, regrasps, jerk and tracking error. Free.
3 · Vision (Nemotron 3.5 Super VL)Two frames of a known-good reference demo plus six frames of the episode, via Nebius Token Factory. Only visible evidence reaches the retake list.
4 · Report (Nemotron 3 Ultra)Ultra writes the summary; code computes every number and hotspot, and a validator removes any claim the data does not support.
5 · Fix guidance (Tavily + Nemotron 3 Ultra)At audit time, Tavily searches LeRobot docs and issues for each problem found. Ultra summarizes only what the sources say, and code keeps a point only if its quote is verified in an official source.

Cost: about $1.10 per 1,000 episodes. Reads LeRobot v2 and v3 datasets straight from Hugging Face without downloading the videos. One command: retake audit <dataset>.
